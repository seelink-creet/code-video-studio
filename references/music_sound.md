# 配乐与声音

## 1. 先问用户（给选项）
> 声音想怎么做？
> A **从曲库挑一首现成音乐**（真乐队质感，最省心）【默认】——我出 2–3 个候选预览（同一画面配不同曲子），你直接看着选
> B **用代码作曲**（MIDI + 乐器采样，可精确卡每个画面节拍，但要多轮调）
> C **纯合成**（芯片音/电子，适合像素、科技风）
> D 你提供音乐（请确认你有使用权）
> 另外：音乐来源走 **付费授权** 还是 **免费/开源**？（见第 2 节；商用项目建议付费或 CC0/CC BY）
音效默认：按动作类型用代码合成（`scripts/sfx_synth.py`），需要真实质感（风、雨、布料、脚步、呼吸）时补充实录素材。

## 2. 素材来源的两个方向
**不要在技能里固定某一首曲子或某一条录音**：每支片子按需求现找，并逐条核对许可。

### 2a. 付费 / 授权曲库与音效库
- 类型：订阅制素材站（音乐 + 音效）、单曲购买的版权音乐站、音效包一次性买断、平台内置商用音乐库。
- 先确认授权覆盖范围：**用途**（个人/商用/客户项目/广告投放）、**平台**（全网还是单一平台）、**期限**（永久还是订阅期内发布有效）、**地域**、是否允许剪辑、是否需要署名、客户项目是否要单独授权。
- 保存证据：订单收据、授权证书或下载时的许可页（PDF/截图，带日期和曲目 ID），连同成片一起归档，写进 `LICENSES`。平台若发出版权认领，用这些证据申诉。
- 平台内置音乐通常只能在该平台使用，导出到别处会失去授权。

### 2b. 免费 / 开源素材
| 许可 | 能否商用 | 要求 | 结论 |
|---|---|---|---|
| CC0 / 公有领域 | 可以 | 无需署名（署名是礼貌） | 首选 |
| CC BY | 可以 | **必须署名**：作者、作品名、许可、来源链接，按作者页给的格式 | 可用 |
| CC BY-SA | 可以 | 署名 + **衍生作品须以相同许可发布**（你的配乐/成片可能也要按 SA 发布） | 慎用；商用或客户项目尽量避免 |
| CC BY-NC（含 NC-SA、NC-ND） | **不能商用** | — | 商用项目不可用 |
| CC BY-ND | 视情况 | **不得修改**（剪辑、变速、混音都算修改） | 基本不可用 |
| “免版税 / Royalty-free” | 看具体条款 | 每个网站条款不同，有的禁止脚本批量下载、有的禁止单独转售 | 逐站阅读 |
常见来源类型：作者个人网站发布的 CC BY 曲库、开放音乐档案站、公有领域古典录音库、维基共享资源、CC0 音效站、游戏开发者免费音效包、开源乐器采样库（CC0 / CC BY）。

**规则**：每用一条素材，就打开它的许可页核对（许可会变、转载站常标错），把“名称 / 作者 / 来源链接 / 许可 / 核对日期 / 是否修改”记进项目的 `LICENSES.csv`；CC BY 的署名原文写进发布文案（视频简介、片尾或置顶评论，按作者要求）。许可不清楚的素材不用。

## 3. 代码作曲（选项 B）
- pretty_midi 写谱 → 用乐器采样演奏。乐器采样优先 CC0，其次 CC BY（需署名）。
- **（可选）开源采样器**：例如开源项目 lemo-opuscar（github.com/lemomo-ai/lemo-opuscar，MIT 许可）里的 Python 采样器，**可选，不装也能完成整个流程**。用途：把代码写的 MIDI 用真实乐器采样渲染成音频，听起来比通用 GM 合成音色好很多。不用它的替代方案：sfizz 渲染 SFZ 采样库；FluidSynth + 高质量 SoundFont；或干脆改用选项 A 的现成曲库。
- 避免通用 GM 音色（“MIDI 感”明显）。
- 坑：部分采样文件名标的音高比实际**低一个八度**，用 pyin/yin 实测基频。
- 和声要有发展：每段换调/换和声/换配器，**不要整片循环同一和弦进行**。
- 低频 20–120 Hz 相对其他频段约 −3 dB；pad 不低于 MIDI 48。
- 变速时声音跟着走：近定格 → 收成持续音/吸气/近乎无声；猛冲 → 涌起 + 定音鼓**滚奏**（不是敲击）。持续和弦单独渲染再变速，后面的音不会漂。

## 4. 现成曲子贴画面（选项 A）
- 尽量**一首曲子一镜到底**：选一个偏移，让曲子自己的段落入口（乐队/鼓进入）落在画面最重要的节拍上：`music_fit.py fit --entry <曲子时间> --beat <画面时间>`。
- 必须剪时：只在小节线剪，挑和声相似的小节做切点，20–30 ms 交叉淡化；常见三段式：曲子开头 → 在冲击点切进更饱满的段落 → 最后切进曲子真正的结尾，终止和弦落在标题/定格下。
- 预备/定格时可以把音乐压出一个“洞”，让冲击落地。
- 先用 `music_fit.py analyse` 找候选入口（能量跳升的小节线）和“呼吸点”（适合放近定格）。
- 剪辑过的 CC BY 曲子，署名后注明“(edited)”。

## 5. 音效
- **按动作类型分家**：落地、whoosh、定格、光/玻璃、点击、碎裂、充能、结尾收束……每类 3 个以上变体轮换，禁止连用同款。
- 禁止弹簧滑音、卡通多普勒（音高抖动 ≤±0.5 半音）；充能用持续音，不用上行滑音；带音高的音效放在音乐调内的五声音阶上。
- 不加 knock/tap 之类的转场音效；用 J-cut（声音先于画面 0.3–0.5 s）和 L-cut（声音拖过切点）。
- 环境声在切镜处等功率交叉淡化（约 0.6 s），不硬切；时间流逝 = 一层淡出、另一层淡入。
- 实录素材处理：用能量包络找可用片段入点（每 50 ms 算 RMS，比峰值低 20 dB 以上的起点）；有咔声先 declick；反向呼吸做吸气时结尾淡出约 120 ms。

## 6. 叙事片（有旁白/对白）四层
旁白/对白 ＞ 拟音（每个手部动作对点）＞ 环境声底（连续铺底）＞ 音乐（稀疏、压在底下）。旁白比音乐高约 10 dB；旁白和关键拟音出现时 sidechain 压低音乐。
TTS：edge-tts 等（用新版本，旧版本可能被服务端拒绝）；叙事可选较年轻自然的音色，语速放慢约 15–20%；不支持停顿标记时在逗号处拆句、拼接真实停顿。想要真正的亲密感，用真人录音。注意 TTS 服务本身的商用条款。

## 7. 混音与母带
- 推荐默认：网络平台 **−14 LUFS**（偏安静、动态大的片子 −16），**真峰值 ≤ −1 dBTP**。
- 两遍 loudnorm（线性）+ 限幅；**AAC 会抬高真峰值，必须编码后复测**，超标回退增益重编（`scripts/master_audio.py` 自动做）。
- 音效总线一般比音乐低 3–6 dB；冲击点可给音乐 1–2 dB 小 dip。
- AI 听不到声音时：画电平曲线、检测 onset 和音高、导出纯音效/纯音乐分轨分别检查；必要时请用户戴耳机听一遍并只回答“哪一秒不舒服”。

## 8. 署名格式（模板）
- CC BY 音乐：`"曲名" by 作者 — licensed under CC BY 4.0 — 来源链接 (edited)`（若作者页给了指定格式，**照抄作者的格式**）
- CC BY 采样：`乐器名 samples: 采样库名 by 作者 — CC BY 3.0`
- CC0 素材：可写 `Additional sounds: 来源站名`（非必须）
- 字体：`字体名 by 作者 — SIL Open Font License 1.1`
