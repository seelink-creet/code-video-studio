# 技术路线菜单

标记：**✅ 已在多支成片中验证** ／ **🟡 做过样张或测试，未完整交付** ／ **⬜ 未验证**（仅调研，选它要先做 5 秒技术测试，预留试错时间）。
难度：★ 半天内上手 ／ ★★ 1–2 天 ／ ★★★ 需要专门调参或新工具链。
“示例”一栏均为**虚构的示意场景**，用来帮用户理解，不是真实作品。

向用户介绍时，每项用一句话说“适合什么”，并标出推荐与风险。

## A. 逐帧程序渲染（Python）—— 默认路线
| 技术 | 适合什么 | 难度 | 状态 | 示例（虚构） |
|---|---|---|---|---|
| PIL + numpy 逐帧绘制，rawvideo 管道进 ffmpeg | 几乎所有 2D：纸面、文字、图形、像素、合成 | ★ | ✅ | 一张纸上墨点慢慢长成一行字 |
| OpenCV 加速（线、重映射、模糊、透视） | 大量线条/粒子/扭曲，比纯 PIL 快很多 | ★ | ✅ | 上千条光线从中心放射 |
| 低分辨率网格 ×N 最近邻放大 | 像素画，硬边清晰 | ★ | ✅ | 270×480 网格 ×4 → 1080×1920 |
| 多进程分块渲染 + concat | 加速长片，可续渲 | ★ | ✅ | 任何超过 20 秒的片子 |
| 超采样（2×/4×）后缩小 | 细线、小字、小物体抗锯齿 | ★ | ✅ | 远处的小字依然清楚 |

## 选择建议
- 先问“观众要感受到什么”：重量感、不可逆的时刻才值得上真物理；其余用脚本动画 + 噪声更好看也更可控（艺术真实优先于物理正确，冲击时可额外加初速度、降重力、延长滞空）。
- 没有特别要求：**A + B 的 Python 路线**最稳；大量排版模板化可考虑 Remotion/HTML（未验证，先测）；真 3D 先试 numpy 2.5D，不够再上 Blender/three.js。
- 混合：Python 产出模拟/质感层 + 框架做排版合成，可行但未验证。
